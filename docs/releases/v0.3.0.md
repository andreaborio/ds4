## Summary

Hebrus 0.3.0 is the first source release under the Hebrus name. It adds
canonical Hebrus commands and a machine-readable capability contract, updates
the exact Qwen release profiles, and retains the focused Apple Silicon, Metal,
and ExpertMajor v2 support boundary. Unsupported artifact layouts and retired
distributed options fail closed; CPU remains reference and debug only, while
CUDA and ROCm sources are absent.

## Changes

- Canonical `hebrus*` commands with same-binary `ds4*` compatibility aliases.
- Schema-1 `--capabilities=json`, staged installation, and reproducible
  source-bundle tooling.
- Stable Qwen MLX Affine4/group-64 as the recommended artifact, opt-in
  Q2_K_XL Beta, and retired Q4_K_S rejection-only admission.
- Qwen guarded-SSD safety and correctness updates, executable-relative Metal
  resources, DeepSeek conversational cache retention, and the HC stride
  correction with a generated-text regression check.

See the [changelog](../../CHANGELOG.md) for release highlights and compatibility
details.

## Supported configurations

The authoritative matrix is the
[runtime support contract](../contracts/RUNTIME_SUPPORT.md). Relative to
v0.2.0, Stable Qwen Affine4 has a qualified 16 GiB guarded-SSD capacity and
safety lane through a 131,072-token prompt plus 128 greedy decode tokens; this
is not a speed claim. Q2_K_XL Beta retains a 64 GiB floor and a 32,768-token
boundary. DeepSeek V4 Flash and GLM 5.2 retain their 64 GiB floors. The Qwen
24 GiB lane remains pending physical sustained qualification.

## Source integrity and build provenance

Download all three source assets together. Verify `SHA256SUMS` with
`sha256sum -c SHA256SUMS` on Linux or `shasum -a 256 -c SHA256SUMS` on macOS.
The JSON manifest records the resolved release commit as full and 12-character
SHAs, plus the commit timestamp, archive size, member count, and archive
SHA-256. The GitHub tag and Release bind `v0.3.0` to that commit. Builds from
the archive must pass the manifest's `git_commit_short` as `BUILD_GIT_SHA`;
redistributable builds should also set `NATIVE_CPU_FLAG=`.

## Compatibility and migration

The five `ds4*` names remain aliases in this release. The `DS4_*` namespace
remains canonical for documented runtime settings, and serialized `ds4`-owned
identifiers are unchanged. This does not revive old model containers or
establish a later release-line alias promise. See the
[migration guide](../guides/MIGRATING_TO_HEBRUS.md) and
[brand contract](../contracts/BRAND_COMPATIBILITY.md).

## Validation

The exact tag target, final asset hashes, exact hosted-job links, and exact-commit
model-backed evidence belong to the
[GitHub Release](https://github.com/andreaborio/hebrus/releases/tag/v0.3.0).
They are intentionally external to this source tree because they exist only
after the release commit is finalized. Historical benchmark records remain
scoped to their recorded commits and hardware.

## Known limitations

- This is a source-only distribution; no prebuilt or notarized application is
  included.
- Production inference is Apple Silicon and Metal, using only the exact
  artifacts in the support contract.
- Qwen 24 GiB remains pending; Q2_K_XL is Beta and not full-window qualified.
- The local server has no built-in authentication; `hebrus-agent` remains
  alpha.
