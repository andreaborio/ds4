# Cross-Engine KV Quantization

Status: Qwen research tranche implemented behind `DS4_QWEN_KV_TQ4=1`.
Production defaults and snapshots are unchanged; DeepSeek and GLM remain
explicitly planned, unimplemented surface lanes.

## Decision Boundary

DS4 will not embed the `turbovec` Rust or Python package. That project is an
approximate-nearest-neighbor index: it demonstrates related rotation and
quantization ideas, but it does not implement DS4's online attention-cache
lifecycle, mmap/SSD ownership, Metal kernels, or snapshot contract. Its
current search path also materializes additional in-memory layouts, so using
the crate directly would not establish a RAM reduction for inference.

The relevant research input is the
[TurboQuant paper](https://arxiv.org/abs/2504.19874). The first DS4 format is a
native, deterministic 4-bit serving candidate informed by the paper and by
the merged [vLLM TurboQuant serving path](https://github.com/vllm-project/vllm/pull/38479):

- keys use L2 normalization, a deterministic signed Walsh-Hadamard transform,
  Gaussian Lloyd-Max 4-bit indices, and one F16 norm per vector;
- values use per-vector min/max uniform 4-bit indices and F16 scale/minimum;
- two dimensions are packed low-nibble first into one byte;
- format identity is `DS4_KV_TQ_FORMAT_VERSION == 1`.

This is not a claim that every surface in every model can use the same
algorithm. The shared code defines packing and checked byte geometry; each
model owner must separately prove that a surface has key, value, or other
semantics before choosing a format.

The merged upstream serving design intentionally omits QJL residuals and
reports non-zero quality movement for its 4-bit presets. Upstream bug reports
also cover [out-of-bounds long-context access](https://github.com/vllm-project/vllm/issues/39998)
and [speculative-decoding corruption](https://github.com/vllm-project/vllm/issues/40831).
Those are negative design inputs for DS4: packed-cache promotion requires
explicit long-prefill, continuation, and speculative-frontier gates and cannot
inherit a "quality neutral" label from the paper.

## Shared Storage Contract

`ds4_kv_quant.h` names every planned surface with:

- model family and semantic surface kind;
- layer count and capacity rows;
- vectors per row and vector dimension;
- the exact storage format.

`ds4_kv_surface_plan_checked()` computes packed payload, metadata, vector
stride, row stride, and total bytes with overflow checks. It deliberately has
no fallback format and no model-shape inference. It rejects cross-family
surface kinds, value coding on non-value surfaces, and non-power-of-two TQ4 key
dimensions. A caller that cannot name the surface and geometry must fail before
allocation.

The TQ4 key row is:

```text
[ceil(d / 2) bytes Lloyd-Max indices][F16 L2 norm]
```

The TQ4 value row is:

```text
[ceil(d / 2) bytes uniform indices][F16 scale][F16 minimum]
```

The Q8 comparison format is:

```text
[d signed-byte payload bytes][F16 scale]
```

The scalar C implementation is used only for deterministic conformance
vectors. It is not a CPU production fallback. The Qwen research Metal path
packs projected K/V rows directly into persistent byte buffers and consumes
them during attention without allocating a global F32 dequantized cache.

While the hardware campaign is active, `DS4_QWEN_TQ4_DECODE` selects
`auto`, `serial`, `parallel`, `split`, `reuse8`, or `flash`. These are
research strategies under the parent `DS4_QWEN_KV_TQ4=1` experiment, not
supported user-facing modes. They deliberately keep different concurrency
and staging choices available for cross-generation comparison:

- `serial` is the correctness-first token-loop kernel;
- `parallel` assigns independent cache slices to SIMD groups;
- `split` uses global split-K partials and a reduction pass;
- `reuse8` shares dequantized two-token tiles across Qwen's eight query heads
  per KV head;
- `flash` dequantizes the live layer to reusable F16 staging and invokes
  vector FlashAttention;
- `auto` is the current composite experiment, not a production policy.

An unknown selector fails closed. No strategy is removed merely because it
loses on one SoC: all remain available until the 16 GiB, 32 GiB, and M5
cohorts support a final policy decision. The research selector and losing
implementations must then be removed before promotion.

The 16 standard-normal TQ4 centroids are generated by
`tests/gen_kv_quant_centroids.py`. Its trapezoidal Lloyd-Max solver follows
the documented upstream distribution, has a `--check` mode, and is part of
the model-free gate. Hand-editing the generated table is a test failure.

## Model Surface Map

| Engine | Existing persistent surface | Current storage | Candidate boundary |
| --- | --- | --- | --- |
| Qwen3.6 | K and V for ten full-attention layers, two KV heads, dimension 256 | separate F32 K/V buffers | TQ4 key and TQ4 value; recurrent DeltaNet state remains unchanged |
| DeepSeek V4 | one raw sliding-window MLA row per layer, width 512 | F32 ring, bounded by the raw-cap policy | classify the combined row before selecting a format; it is not ordinary full K/V |
| DeepSeek V4 | compressed attention rows, width 512 | F16 on Apple | quantify separately from the raw ring; preserve ratio-4/ratio-128 row ownership |
| DeepSeek V4 | ratio-4 indexer rows, width 128 | F32 | key-like candidate only after index-selection drift tests |
| GLM 5.2 | compact `kv_lora`, width 512, and `k_rope`, width 64, for 78 normal layers | F16 on Apple | separate formats/kernels; `kv_lora` reconstructs both attention operands and is not a value vector |
| GLM 5.2 | indexer key, width 128, on 21 indexer-owning layers | F16 on Apple | key-like candidate after top-k selection equivalence |
| GLM 5.2 | expanded full K/V | disabled | must remain disabled; quantization must not restore this cache |

Qwen is the first implementation lane because it is the only current engine
with semantically ordinary full K/V buffers and the largest avoidable
per-token precision:

```text
F32 K/V cache = 10 layers * 2(K,V) * 2 heads * 256 * 4
              = 40,960 bytes/token

TQ4 v1 cache = 10 layers * 2 heads * (130-byte K + 132-byte V)
             = 5,240 bytes/token
```

At 32,768 tokens this isolates 1.250 GiB of current F32 K/V versus
0.160 GiB for the packed candidate, a 1.090 GiB payload reduction. The
existing four bytes of non-KV per-token graph state are excluded from both
numbers. These are allocation calculations, not measured RSS savings.

DeepSeek and GLM may show smaller savings because they already store important
long-lived surfaces in F16 or in model-native compressed form. For example,
GLM's current 32K compact cache is approximately 2.906 GiB:

```text
78 * 32768 * (512 + 64) * 2
+ 21 * 32768 * 128 * 2
```

The GLM figure makes the engine worth optimizing, but it does not authorize
applying the Qwen key/value codec to `kv_lora`.

## Metal Integration Order

1. Keep the checked planner and scalar reference deterministic on every build.
2. Add Qwen fused pack/store and attention-time decode for full-attention
   layers only. This research tranche is complete; recurrent state, routing,
   and SSD expert ownership did not move.
3. Qualify Qwen F16, Q8, and TQ4 candidates against the same F32 control.
   Preserve the TQ4 execution variants through the full cross-hardware
   campaign; make the removal decision only from the combined 16 GiB,
   32 GiB, and M5 evidence.
4. Audit DeepSeek raw MLA, compressed attention, and indexer surfaces as three
   independent semantic changes. Do not combine cache-ratio changes with
   quantization.
5. Audit GLM `kv_lora`, `k_rope`, and indexer caches independently while
   retaining SSD-only admission and the absence of expanded full K/V.
6. Only after all affected engines qualify, make the selected format and
   execution policy the singular default, then remove experiment switches,
   losing kernels, and campaign-only logging.

Every production implementation must account for:

- packed payload and metadata;
- alignment and allocator rounding;
- per-command/threadgroup scratch;
- prefill conversion peaks;
- split-K/reuse scratch;
- snapshot staging and speculative rollback;
- host RSS, Metal allocation, memory pressure, swap, and model mmap residency.

A smaller persistent buffer with a larger global dequant or continuation
workspace is not an accepted optimization.

## Snapshot And Restore

The reference format version does not change snapshots because production
still serializes the existing stable representation. Before a packed cache can
become live, the owning checkpoint code must record:

- family and surface kind;
- TQ format version;
- vector dimension, vector/row stride, layer count, and capacity;
- deterministic sign seed derivation;
- live logical row counts and ring/frontier state.

Restore must reject a missing, unknown, cross-family, or geometry-incompatible
identity. It must never reinterpret F32/F16 payload as TQ4 or silently rebuild
from canonical routed weights.

## Qualification Matrix

The controlling requirements remain `CONTRIBUTING.md` and
`QA_BEFORE_RELEASES.md`.

- Model-free: checked arithmetic, invalid geometry, nibble order, deterministic
  key vectors, zero vectors, value error, centroid generator check, Metal
  bounds tests, `make premerge`, and `git diff --check`.
- Per candidate and engine: fresh-process short, medium, large, and 32K
  baseline-versus-candidate cohorts.
- Attention/KV additions: 65K and 100K frontiers, continuation prefill,
  checkpoint restore, multi-turn reuse, and speculative partial/full accepts.
- Shared code: qualified Qwen, DeepSeek, and GLM runs under every supported
  AUTO/resident/SSD mode. GLM resident requests must still fail closed.
- Evidence: exact artifact and source identities, resolved plan, token/logit or
  attention agreement, TTFT, prefill/decode throughput, RSS, Metal bytes,
  conversion/scratch peak, pressure, and swapout delta.

Short-context evidence may reject a format but may not promote it. An abort,
changed resolved plan, swapout, competing inference process, or missing peak
measurement invalidates the complete comparison cohort.
