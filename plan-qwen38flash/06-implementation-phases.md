# Implementation phases, ownership and merge gates

## 1. General sequencing rule

Each phase ends in a reviewable, green commit. Agents do not begin a dependent
phase because a file exists; they begin only when the stated exit gate is
recorded. Large optimizations are separate commits from semantic implementation.
Do not assign two agents concurrently to `ds4.c`, `ds4_metal.m` or a shared
manifest struct. Parallel work is limited to disjoint reference/tests/tools
after interfaces are frozen.

Suggested branch prefix: `feat/qwen4exp-<phase>`. Every PR description states
the exact source revision, supported/non-supported scope, byte owners changed,
tests run and whether it alters shared DeepSeek/GLM/Qwen3.6 code.

## 2. Phase 0 — decision record and pinned evidence

### Deliverables

- ADR: exact model identity, text-only scope, Metal-only production, context
  rollout, new family/profile IDs, ExpertMajor v2 reuse, PLE v1 embedded extent,
  permitted codecs, MTP/vision exclusions and release gates.
- Immutable local source manifest for HF revision `de4b8e4...`: 131 shard hashes,
  1,658 tensor names/shapes/dtypes, config/tokenizer/template/generation hashes.
- License review record for Qwen Community License 1.0 before artifact
  distribution; do not assume Apache-2.0.
- Regenerated diagrams/formula check against pinned Transformers commit.
- Model contract unit-data JSON containing exact dimensions and 48 layer types.

### Exit gate

Two reviewers can independently reconstruct the same source inventory and agree
on every closed field. No production/runtime code yet.

## 3. Phase 1 — pure profile and scalar oracles

### Files

Add `ds4_qwen4exp.[ch]`, `ds4_qwen4exp_ref.[ch]` and model-free tests. These
files cannot depend on Metal or a full checkpoint.

### Work items

1. immutable descriptor and checked byte formulas;
2. zero-centered and conventional gated RMSNorm oracles;
3. GR read/injection/apply/final-mixer oracle;
4. GDN single-step reference with exact 16->48 repeat-interleave;
5. exact F32 router softmax/top-10/tie/renormalization;
6. QSA raw grouping, partial RoPE, ReLU-per-head score, deterministic top-512,
   expansion and per-query tail;
7. uint64 SplitMix multiplier generation, prime/head offsets, bigram/trigram
   hashes and EOS behavior;
8. PLE gate and dilated-convolution state reference;
9. state reset/copy/rewind helpers on tiny dimensions.

The oracle favors clarity: ordinary loops, checked shapes, no SIMD, no calls to
the production Metal helper being tested.

### Exit gate

Golden vectors generated by pinned Transformers pass for every primitive; ASan/
UBSan model-free tests pass; adversarial dimensions and hash overflow cases pass.

## 4. Phase 2 — artifact descriptors and converter dry run

### Files

Extend `ds4_expert_store.[ch]` with a new family/profile without altering v2
layout; refactor `gguf-tools/ds4-expert-major.py` to descriptor-driven geometry;
add `ds4_ple_store.[ch]` parser/validator and a converter profile module.

### Work items

- parser/writer tests for new ExpertMajor family 48x512 and all corruption cases;
- PLE v1 fixed-page format, hashes/digests, locate-row arithmetic and boundary
  tests with a synthetic 100-row store;
- dry-run source mapping that loads only headers/index and outputs the complete
  source->destination inventory;
- chunked direct conversion of a few real tensors/shards into a miniature
  artifact; no 180B BF16 materialization;
- codec role table and norm-convention manifest fields;
- verify/install protocol using temporary file, fsync and atomic rename.

### Exit gate

Converter `--dry-run` consumes every source identity exactly once according to
profile; miniature build verifies with the runtime parser; Qwen3.6 converter and
store tests are unchanged/green.

## 5. Phase 3 — exact loader/admission, no execution

### Files

Add family/profile dispatch and a Qwen4Exp loader partition. Keep changes to
common `ds4.c` limited to small dispatch calls into the partition.

### Work items

- exact `qwen4exp` metadata validation including uint64 arrays;
- tensor inventory/binding with separate base, PLE, MTP and vision classifications;
- exact non-routed physical/page span construction and ownership proof;
- ExpertMajor/PLE embedded extent validation with mutual disjointness;
- tokenizer/template/special ID digest validation;
- text-only and MTP-not-executed policies;
- option/capability rejection before graph allocation;
- diagnostic summary and machine-readable admission report.

### Exit gate

Every negative fixture fails on its intended field before Metal allocation;
accepted miniature artifact reports exact owners; fuzz/overflow tests and all
existing loader/metadata tests pass.

## 6. Phase 4 — tokenizer and text contract

This can run parallel to late Phase 3 only after profile and digest interfaces
are frozen; it must not touch loader internals.

### Work items

- pinned regex/BPE/special vocabulary implementation or safe reuse;
- new chat format/alias only if required, preserving Qwen3.6 API;
- reasoning-effort/template/tool-call fixtures and provenance-safe rendering;
- pad/valid-vocab/sampling boundaries;
- no image/video acceptance in the text profile;
- server code remains disabled behind unsupported capability until Phase 10.

### Exit gate

Encode/decode and rendered byte fixtures match pinned Transformers across the
full test corpus, including literal control-token attacks and malformed Unicode.

## 7. Phase 5 — resident float/mixed correctness graph

### Work items

1. allocate explicit Qwen4Exp graph/state with checked byte report;
2. implement embedding->four-stream residual;
3. simple GR Metal kernels;
4. GDN decode and exact sequential prefill scan, FP32 state;
5. exact 512/top-10 router, resident routed/shared MoE;
6. QSA dense reference only for contexts `<=2051`, with raw index cache;
7. PLE with a tiny fully resident synthetic/real slice store;
8. final GR mixer and output head; no nonexistent output norm;
9. transactional one-token commit and state reset.

Use higher precision/small contexts if necessary; this phase proves graph math,
not target memory.

### Exit gate

Layer and final logits match pinned fixtures at declared tolerances for token-by-
token and chunked input. Failure injection after each graph stage leaves public
frontier/logits/state unchanged. Metal validation and ASan host tests pass.

## 8. Phase 6 — native sparse QSA and long state

### Work items

- raw index cache co-owned with main KV slots;
- tiled score+deterministic top-512 without full score matrix;
- compact selected-K/V gather and online-softmax attention, never dense QxK mask;
- per-query incomplete tail and padded/multi-sequence isolation;
- incremental pooled-key cache optimization behind parity selector;
- rewind/shift/copy/fork/reset for KV/index groups/tails;
- optional Q8/Q4 KV research only after BF16 path is stable.

### Exit gate

Dense parity for all visible keys `<=2051`; selected ID fixtures above budget;
single-shot/chunk/decode parity; no QxK allocation counter; tests through 65,537
and model-backed 100K; pooled/raw cache selections identical.

## 9. Phase 7 — PLE store streaming

### Work items

- bounded page table/cache, leases, generations and eviction;
- exact hash planner and global prefill dedup/coalescing;
- asynchronous `pread` fallback into shared ring buffers;
- evaluate `MTLIOCommandQueue` through capability probe as a Tier-A candidate,
  while retaining authoritative fallback;
- overlap reads with embedding/layer 0 and dependency-scoped wait at PLE;
- fused quantized row decode/gather and PLE compute;
- cold/warm telemetry, read amplification and pressure/failure injection.

### Exit gate

Resident and streamed PLE row/model outputs agree; truncated/corrupt stores fail;
cancellation/error unwinds every lease/ticket; real overlap is evidenced; no
unbounded mapping first-touch or global GPU wait; cold and warm tests pass.

## 10. Phase 8 — target quantization and resident routed experts

### Work items

- stream BF16/FP8 source tensor tiles directly to role-specific 1/2/3/4/8-bit
  candidate formats without full expansion;
- tail-safe encoders/decoders for widths 160, 128, 320 and 640;
- mixed-codec manifest and exact Metal selectors;
- M5 top-10 expert GEMV, fused gate+up/SwiGLU, down and sum10;
- grouped expert prefill GEMM with stable scatter;
- keep router/indexer/norm/GDN-state sensitive roles at conservative precision;
- full artifact quality bakeoff.

### Exit gate

At least one artifact fits the declared M5 AUTO budget with headroom and no swap;
primitive/logit/greedy/quality gates pass; no selected expert reads unselected
payload; Qwen3.6 codecs remain bit-for-bit unchanged.

## 11. Phase 9 — AUTO memory policy and performance qualification

### Work items

- owner/lifetime byte formula integrated into residency resolver;
- primary `resident routed + streamed PLE` plan;
- generalized expert-cache forced control with 481-record floor;
- phase-specific prefill/decode workspace and cache growth gates;
- normal pressure snapshots and safe shrink/failure boundaries;
- M5 fused GR/GDN/QSA refinements only from profiler evidence;
- full matrix and A/B/B/A protocol in `08-performance-plan-m5-pro.md`.

### Exit gate

Normal AUTO on physical M5 Pro 64 GB is correct, faster than the declared
baseline/control, within memory/headroom/no-swap limits, and reproducible. Forced
SSD and resident/reference controls distinguish I/O from compute bottlenecks.

## 12. Phase 10 — product exposure and other Metal tiers

### Work items

- server alias/capability only after core support gate;
- downloader/release contract and checksums;
- `RUNTIME_SUPPORT.md`, code map, QA/release docs and benchmark records;
- physical Tier B/C devices, explicit maximum contexts/artifacts;
- shared runtime regressions DeepSeek, GLM, Qwen3.6;
- concurrency, multi-turn and long-duration stability.

### Exit gate

Each advertised tier has physical evidence. Unsupported combinations reject
early. Release docs describe the text-only, no-MTP/no-vision boundary exactly.

## 13. Phase 11 — optional MTP, then vision

Separate ADR and artifacts. MTP consumes the full 10,240-wide residual, requires
transactional target state for every candidate, and may reuse base QSA selection
only after token identity proof. Vision is on-demand and needs full multimodal
MRoPE/PLE placeholder/template tests. Neither can delay or weaken the base text
release.

## 14. Agent assignment template

For each task give an agent exactly:

```text
phase and prerequisite commit;
allowed files and forbidden shared files;
closed source/profile revision;
semantic equations or API contract;
required positive/negative fixtures;
memory owners introduced and byte formula;
commands/tests to run;
exit evidence to paste into handoff;
explicit non-goals.
```

One integration owner reviews arithmetic, ownership and failure paths before
merging. Performance agents cannot alter oracle code. Converter agents cannot
invent runtime tolerance. Documentation is updated in the same commit as a
contract change, not deferred to release week.
